\section{Argumentos técnicos}
\subsection{Compatibilidad con herramientas de desarrollo}
SerenityOS define un entorno de desarrollo basado en herramientas estándar del ecosistema de compilación en Linux. La guía de construcción especifica dependencias y versiones mínimas de componentes críticos del entorno: compilador anfitrión moderno, CMake (versión mínima indicada), sistema de construcción (Ninja) y un entorno de ejecución virtualizado con QEMU (versión mínima indicada).

El flujo de trabajo de construcción incluye utilidades auxiliares para la toolchain cruzada, generación de imágenes y tareas de soporte del ciclo de desarrollo (por ejemplo, sincronización y caché de compilación). La misma guía describe instalación por distribución y casos comunes de configuración.

Herramientas utilizadas en el flujo de desarrollo:
\begin{itemize}
	\item Sistema de build: CMake y Ninja
	\item Ejecución/virtualización: QEMU
	\item Compilación: GCC o Clang (versiones recientes)
\end{itemize}

\subsection{Modularidad y posibilidad de adaptación}
SerenityOS presenta una organización del código orientada a separar áreas funcionales del sistema (por ejemplo, kernel, bibliotecas, servicios y aplicaciones). Esta estructura delimita responsabilidades y separa capas de ejecución.

En el desarrollo, el repositorio contiene componentes con directorios y convenciones de construcción que distinguen código del sistema, bibliotecas y aplicaciones, manteniendo dependencias explícitas a través del sistema de build.

El flujo de construcción contempla compilación cruzada y soporta múltiples arquitecturas, con directorios de salida y objetivos de ejecución diferenciados por arquitectura.

\subsection{Lenguaje de programación utilizado}
SerenityOS es un proyecto cuyo desarrollo se realiza principalmente en C++. En el repositorio se observa C++ como lenguaje predominante y la presencia de lenguajes auxiliares para utilidades, scripts y partes del entorno.

El entorno de construcción exige un compilador anfitrión moderno con soporte de características recientes de C++ para construir herramientas del host.

\subsection{Facilidad de compilación, prueba y depuración}
El proyecto utiliza un script principal para tareas del ciclo de desarrollo. El comando estándar construye el sistema, instala los artefactos en un directorio de salida por arquitectura y lanza la máquina virtual. El flujo también incluye un modo de compilación sin arranque de la VM.

Antes de compilar, se requiere instalar un conjunto de dependencias del sistema anfitrión. Se considera el siguiente conjunto de paquetes (dependencias de compilación, herramientas de build, emulación y utilidades auxiliares):
\begin{verbatim}
sudo apt install build-essential cmake curl libmpfr-dev libmpc-dev
libgmp-dev e2fsprogs ninja-build qemu-system-gui qemu-system-x86
qemu-utils ccache rsync unzip texinfo libssl-dev zlib1g-dev
\end{verbatim}

Como requisitos mínimos del toolchain, se solicita un compilador anfitrión moderno con soporte de características recientes de C++ (por ejemplo, GCC 13 o Clang 17 o superior). El entorno establece versiones mínimas de herramientas clave, como QEMU (6.2 o superior) y CMake (3.25.0 o superior). Si se migra desde una versión anterior de CMake, se considera la limpieza del caché de CMake en el directorio de compilación.

\subsection{Escalabilidad para futuras extensiones}
SerenityOS incluye un sistema de \emph{ports} para incorporar software adicional mediante scripts de empaquetado y un flujo de compilación integrado.

El proyecto mantiene documentación complementaria para escenarios de construcción menos comunes y para opciones avanzadas del sistema de build.
